## 本章范围

L20-L30：cross join、inner join、outer join、子查询、exists、组合查询、开窗函数（sum over、rank、row_number、lag/lead）。

涉及的表结构：
- `student`：id（学号）、name（姓名）、age（年龄）、class_id（班级编号）、score（成绩）、exam_num（考试编号）
- `class`：id（班级编号）、name（班级名称）、level（班级级别）
- `student_new`：字段与学生表完全一致的新学生表

「字段顺序和原始表的字段顺序一致」指 SELECT 中先写原始表字段、再写计算字段（如 `class_avg_score`）。

---

### L20 关联查询 - cross join

**语法**：`cross join` 不需要关联条件，直接把左表每一行与右表每一行组合，得到笛卡尔积；逗号分隔的隐式写法与之等价。

**参考答案**：
```sql
select s.name student_name, s.age student_age, s.class_id class_id, c.name class_name from student s, class c;
```

**解析**：需求是将学生表与班级表的所有行两两组合，返回学生姓名（student_name）、学生年龄（student_age）、班级编号（class_id）以及班级名称（class_name）。`cross join` 不需要任何关联条件，直接把左表的 **每一行** 与右表的 **每一行** 组合，结果是两表的 **笛卡尔积**：若学生表有 M 行、班级表有 N 行，结果就有 M × N 行。常用于生成组合数据，实际业务中极少直接使用（会产生大量无意义行）。这里用别名 `s`、`c` 简化表名引用。

---

### L21 关联查询 - inner join

**语法**：`inner join ... on 关联条件` 只保留两表满足条件的行，相当于求交集；`join` 是 `inner join` 的简写，两者等价。

**参考答案**：
```sql
select s.name student_name, s.age student_age, s.class_id class_id, c.name class_name, c.level class_level from student s join class c on s.class_id = c.id;
```

**解析**：需求是根据班级编号匹配，返回学生姓名、学生年龄、班级编号、班级名称、班级级别。`inner join` 通过 `on` 指定关联条件（`s.class_id = c.id`），只把两张表中 **满足条件的行** 组合在一起。凡是 `class_id` 在班级表中找不到对应 `id` 的学生，会被过滤掉。

---

### L22 关联查询 - outer join

**语法**：`left join ... on 关联条件` 保留左表全部行，右表无匹配时补 `NULL`；`right join`、`full outer join` 方向同理。

**参考答案**：
```sql
select s.name student_name, s.age student_age, s.class_id class_id, c.name class_name, c.level class_level from student s left join class c on s.class_id = c.id;
```

**解析**：需求是必须返回所有学生的信息（即使对应的班级编号不存在）。`left join`（即 `left outer join`）在 inner join 的基础上，**保留左表的所有行**；右表没有匹配到时，右表字段用 `NULL` 填充。如果反过来要保留右表全部行，则用 `right join`；两边都保留用 `full outer join`。

---

### L20-L22 小结：join 类型对比

| join 类型 | 匹配条件 | 返回结果 | 无匹配时 | 典型场景 |
| --- | --- | --- | --- | --- |
| `cross join` | 不需要 | 两表行两两组合（笛卡尔积） | 不存在「匹配」概念 | 生成排列组合、测试数据 |
| `inner join` | `on` 条件 | 两表匹配成功的行 | 直接丢弃 | 只想要有关联的数据（如学生都有班级） |
| `left join` | `on` 条件 | 左表全部 + 右表匹配行 | 右表字段补 `NULL` | 主表全量展示（如所有学生及其班级名） |
| `right join` | `on` 条件 | 右表全部 + 左表匹配行 | 左表字段补 `NULL` | 与 left join 方向相反的场景 |
| `full outer join` | `on` 条件 | 两表全部行 | 对应侧字段补 `NULL` | 合并两张表全部数据（MySQL 不支持，可用 union 模拟） |

- `inner join` 与 `left join` 是日常开发中使用频率最高的两种。
- 省略 `on` 条件的 `join` 等价于 `cross join`。

### L23 子查询

**语法**：把一条完整的 SELECT 嵌套进另一条 SELECT 内部，执行顺序「先内后外」。

**参考答案**：
```sql
select name, score, class_id from student where class_id in (select distinct id from class);
```

**解析**：需求是使用子查询获取存在对应班级的学生数据，返回姓名（name）、分数（score）、班级编号（class_id）。子查询就是 **嵌套在另一个查询内部的完整 SELECT**，执行顺序是「先内后外」：先执行内层 `select distinct id from class` 得到所有存在的班级编号列表，再交给外层 `where class_id in (...)` 做过滤。除了 `in`，子查询还可以用在 `=`、`>`、`from` 等位置。

---

### L24 子查询 - exists

**语法**：`exists (子查询)` 只返回布尔值——子查询有结果则为 TRUE、无结果则为 FALSE；子查询中可以引用外层查询的字段（相关子查询）。

**参考答案**：
```sql
select name, age, class_id from student where not exists (select class_id from class where class.id = student.class_id);
```

**解析**：需求是使用 `exists` 获取不存在对应班级的学生数据，返回姓名（name）、年龄（age）、班级编号（class_id）。`exists` 子查询**不返回数据，只返回布尔值**。它与 `in` 最大的区别是：`exists` 子查询中可以使用**外层查询的字段**（这里 `student.class_id` 就是外层行），形成「相关子查询」，逐行判断；加上 `not` 后语义反转，筛出班级表中不存在的学生（class_id 对应的 id 查不到）。

---

### L23-L24 小结：IN vs EXISTS 对比

| 对比维度 | `IN` | `EXISTS` |
| --- | --- | --- |
| 返回内容 | 子查询返回一列值列表，做等值匹配 | 子查询只判断「有没有行」，返回 TRUE / FALSE |
| 是否引用外层字段 | 通常不引用（非相关子查询） | 常引用外层字段（相关子查询） |
| 与 NULL 的关系 | 列表中含 NULL 时可能影响结果 | 不受 NULL 影响 |
| 大数据量性能 | 子查询结果集小时表现好 | 外层表小、子查询走索引时表现好 |
| 可读性 | 写法简洁直观 | 适合「存在性」判断，逻辑更灵活 |

记忆口诀：`in` 问「在不在列表里」，`exists` 问「有没有这么一行」。现代数据库优化器大多会把两者改写为等价执行计划，功能上 `exists` 能表达更多场景（如多字段关联、不等值关联）。

### L25 组合查询

**语法**：`select ... union [all] select ...` 纵向拼接多条 SELECT 的结果；各 SELECT 列数一致、对应列类型兼容。

**参考答案**：
```sql
select name, age, score, class_id from student
union all
select name, age, score, class_id from student_new;
```

**解析**：需求是获取两张表的姓名（name）、年龄（age）、分数（score）、班级编号（class_id）字段，并保留重复的学生记录。`union all` 把两条 SELECT 的结果**纵向拼接**（行数相加），且**不去重**，完全满足「保留重复记录」的要求。如果去掉 `all` 写成 `union`，则会自动去除完全相同的重复行。

---

### L25 小结：UNION vs UNION ALL 对比

| 对比维度 | `UNION` | `UNION ALL` |
| --- | --- | --- |
| 去重 | 自动去除重复行 | 保留全部行，不去重 |
| 性能 | 需要额外排序去重，较慢 | 直接拼接，更快 |
| 结果行数 | ≤ 两表行数之和 | = 两表行数之和 |
| 使用场景 | 需要合并后去重 | 结果本身不重复，或明确要保留重复记录 |

能确认结果不会重复时，`union all` 省去去重开销。本关要求「保留重复记录」，所以答案是 `union all`。

### L26 开窗函数 - sum over

**语法**：`聚合函数(字段) OVER (PARTITION BY 分组字段)`，分组统计但不压缩行数；不写 `PARTITION BY` 时对整个结果集计算。

**参考答案**：
```sql
SELECT 
    id,
    name,
    age,
    class_id,
    score,
    exam_num,
    AVG(score) OVER (PARTITION BY class_id) AS class_avg_score
FROM
    student;
```

**解析**：需求是返回每个学生的详细信息（字段顺序与原始表一致），并计算每个班级的学生平均分（class_avg_score）。普通聚合函数（如 `avg(score)` 单独用）会把多行压缩成一行；而开窗函数 `OVER (PARTITION BY class_id)` 按班级分组计算平均分，但 **每一行原始明细都保留**，每组算出的平均值复制到该组每一行上。

---

### L27 开窗函数 - sum over order by

**语法**：`SUM(字段) OVER (PARTITION BY 分组字段 ORDER BY 排序列 [ASC|DESC])`，聚合范围从整个分组变为分组内第一行到当前行，实现累计求和。

**参考答案**：
```sql
SELECT 
    id,
    name,
    age,
    score,
    class_id,
    SUM(score) OVER (PARTITION BY class_id ORDER BY score ASC) AS class_sum_score
FROM
    student;
```

**解析**：需求是返回每个学生的详细信息（字段顺序与原始表一致），并按照分数升序累加计算每个班级的学生总分（class_sum_score）。在 `OVER` 中加上 `ORDER BY` 后，聚合范围从「整个分组」变为「分组内从第一行到当前行」，实现 **累计求和**（running total）。排序规则（ASC/DESC）会直接改变累加的方向和结果。

---

### L28 开窗函数 - rank

**语法**：`RANK() OVER (PARTITION BY 分组列 ORDER BY 排序列 DESC)`，组内排名，分数相同则并列同排名但跳号（1、1、3）。

**参考答案**：
```sql
SELECT 
    id,
    name,
    age,
    score,
    class_id,
    RANK() OVER (PARTITION BY class_id ORDER BY score DESC) AS ranking
FROM
    student;
```

**解析**：需求是返回每个学生的详细信息（字段顺序与原始表一致），并按照分数降序计算每个班级内的学生排名（ranking）。`rank()` 给每个分组内的行排名：**分数相同则并列同名次，但会跳过后续名次**（如并列第 1 后，下一位是第 3 名）。典型应用是查找组内 Top N（如每个班级的前三名）。

---

### L29 开窗函数 - row_number

**语法**：`ROW_NUMBER() OVER (PARTITION BY 分组列 ORDER BY 排序列)`，组内从 1 开始分配唯一且连续的编号，无并列、不跳号。

**参考答案**：
```sql
SELECT 
    id,
    name,
    age,
    score,
    class_id,
    ROW_NUMBER() OVER (PARTITION BY class_id ORDER BY score DESC) AS row_number
FROM
    student;
```

**解析**：需求是返回每个学生的详细信息（字段顺序与原始表一致），并按照分数降序给每个班级内的学生分配唯一编号（row_number）。`row_number()` 不管分数是否相同，都从 1 开始给组内每一行分配 **唯一且连续** 的编号，不会有并列、不会跳号。它与 `rank` 的差别就在并列时的处理。常用来「每组取前 N 条」：先用 `row_number()` 编号，再在外部查询过滤 `row_number <= N`。

---

### L30 开窗函数 - lag / lead

**语法**：`LAG(列, offset, default)` 取当前行之前的某列值，`LEAD(列, offset, default)` 取当前行之后的某列值；`offset` 默认 1，`default` 是越界时的默认值（默认 NULL）。

**参考答案**：
```sql
SELECT 
    id,
    name,
    age,
    score,
    class_id,
    LAG(name) over (PARTITION BY class_id ORDER BY score DESC) as prev_name,
    LEAD(name) OVER (PARTITION BY class_id ORDER BY score DESC) AS next_name
FROM
    student;
```

**解析**：需求是返回每个学生的详细信息（字段顺序与原始表一致），并按照分数降序获取每个班级内学生的前一名姓名（prev_name）、后一名姓名（next_name）。`lag()` 取 **当前行之前（往上偏移）** 的某列值，`lead()` 取 **当前行之后（往下偏移）** 的某列值。常用于相邻行比较，例如对比「上个月 vs 这个月」的销售额、计算环比增长率。完整语法为 `LAG(列, offset, default)`：`offset` 表示偏移行数（默认 1），`default` 是越界（如第一行没有前一行）时的默认值（默认 NULL）。

---

### L26-L30 小结：开窗函数语法与对比

**统一语法**：
```sql
开窗函数(参数) OVER (
    PARTITION BY 分组列1, 分组列2, ...  -- 可选：按什么分组
    ORDER BY 排序列 [ASC|DESC]          -- 可选：组内按什么排序
    [ROWS BETWEEN ... AND ...]          -- 可选：进一步限定窗口范围（帧）
) AS 别名
```

| 函数 | 作用 | 是否分组（PARTITION BY） | 是否排序（ORDER BY） | 并列时的行为 |
| --- | --- | --- | --- | --- |
| `SUM(score) OVER(...)` | 组内求和 / 累计求和 | 通常需要 | 不加 = 组内总聚合；加了 = 累计求和 | 不涉及排名 |
| `AVG(score) OVER(...)` | 组内平均分 | 通常需要 | 可选 | 不涉及排名 |
| `RANK()` | 组内排名 | 可选 | 必须 | 并列同排名，**跳号**（1、1、3） |
| `ROW_NUMBER()` | 组内行号 | 可选 | 必须 | 无并列，**唯一连续**（1、2、3） |
| `LAG(列)` | 取上一行的值 | 可选 | 通常需要 | 取相邻行数据，与排名无关 |
| `LEAD(列)` | 取下一行的值 | 可选 | 通常需要 | 取相邻行数据，与排名无关 |

- 开窗函数三要素：**聚合/排名/取值函数 + PARTITION BY（分窗）+ ORDER BY（排序）**。
- 开窗函数最大的价值：**分组计算的同时不丢失明细行**，这是普通聚合函数做不到的。
- 排名三兄弟 `rank` / `dense_rank` / `row_number`：并列时分别表现为「跳号」「不跳号」「不并列」，面试高频考点。

## 本章总结

1. **关联查询**：`cross join` 全组合 → `inner join` 取交集 → `left/right join` 保一侧，层层递进；join 的 `on` 条件决定匹配规则。
2. **子查询**：`in` 匹配值列表，`exists` 判断存在性（可引用外层字段），二者都能实现「表 A 的数据在表 B 中有/无对应」。
3. **组合查询**：`union` 去重合并，`union all` 不去重合并，性能优先用 `union all`。
4. **开窗函数**：`OVER (PARTITION BY ... ORDER BY ...)` 一行语法通吃——分组统计（sum/avg over）、累计求和（加 order by）、排名（rank/row_number）、相邻行取值（lag/lead），是数据分析与面试的常用技能。
