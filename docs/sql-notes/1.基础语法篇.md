## 本章概览

本章覆盖 SQL 查询的基础语法，共 13 关（L1 ~ L13），分为三部分：

- **查询基础（L1 ~ L4）**：全表查询、选择查询、别名、常量与运算
- **条件查询（L5 ~ L9）**：`where` 子句、比较运算符、空值、模糊查询、逻辑运算
- **查询进阶（L10 ~ L13）**：去重、排序、截断和偏移、条件分支

L1-L13 依次涉及：全表查询、选择查询、别名、常量运算、WHERE 条件、运算符、空值、模糊查询、逻辑运算、去重、排序、LIMIT 截断偏移、CASE WHEN 条件分支。

各关卡基于学生表 `student`，字段为 `id`（学号）、`name`（姓名）、`age`（年龄）、`class_id`（班级编号）、`score`（成绩）、`exam_num`（考试编号）。后续关卡在已有语法上逐步叠加新内容。

### L1 全表查询


```sql
select * from student
```

**解析**：`SELECT` 是查询关键字，`*` 是通配符，代表数据表中的**所有列**；`FROM student` 指定查询的数据表。该语句返回 `student` 表中每一行的所有字段，是最基础的查询写法。

::: tip 知识点
`SELECT * FROM 表名` 即**全表查询**。`*` 表示「所有列」，无需预先知道表结构，适合快速浏览整张表的数据。
:::

::: warning 注意
`*` 虽方便，但生产环境中更常显式列出所需列：结果集更小、传输更快，且表结构变化时查询结果更可控。
:::

### L2 选择查询


```sql
select name, age from student
```

**解析**：与全表查询不同，选择查询在 `SELECT` 后**明确列出需要的列名**，用逗号分隔，数据库只返回这些列的数据。这样做可减少不必要的数据传输，查询意图也更清晰。

::: tip 知识点
`SELECT 列1, 列2, ... FROM 表名` 即**选择查询**：只返回指定的列。结果列的**输出顺序**由 `SELECT` 后列名的书写顺序决定，姓名在前、年龄在后时须写成 `select name, age`。
:::

### L3 别名


```sql
select name as 学生姓名, age 学生年龄 from student
```

**解析**：别名给查询结果中的列起一个**临时的、可读性更高的名字**，不改变表本身的结构。标准写法是 `列名 as 别名`，`as` 关键字可省略（如 `age 学生年龄`），两种写法等价。`name` 仍是 `name`，只是结果显示为「学生姓名」。

::: tip 知识点
别名语法：`列名 [AS] 别名`。`AS` 可省略；别名只在**本次查询的结果**中生效，不修改原始表。列名为英文缩写或包含计算表达式时，别名能让结果更直观。
:::

### L4 常量和运算


```sql
select name, score, score * 2 as double_score from student;
```

**解析**：`SELECT` 中不仅可直接列出列名，还可以写**表达式**。`score * 2` 对每一行的 `score` 做乘法运算，`2` 是常量（固定的数值），运算结果作为新的一列输出。表达式列通常搭配别名（`as double_score`），否则结果集的列名会直接显示为 `score * 2` 这一长串表达式。

::: tip 知识点
`SELECT` 支持常量与四则运算（`+`、`-`、`*`、`/` 等），运算基于每一行数据**逐行**进行，结果列宜用别名命名。常量和运算不仅限于数字，也可对文本做拼接等字符串操作。
:::

### L5 条件查询 where


```sql
select name, score from student where name = '鱼皮'
```

**解析**：前面的查询每次都返回整张表，`where` 子句用于**过滤行**：只有满足条件的数据行才会被返回。`where name = '鱼皮'` 中的 `=` 是比较运算符，判断 `name` 列的值是否等于字符串 `'鱼皮'`。

两个细节：一是字符串常量必须用**单引号**包裹，数字常量不用；二是 `where` 子句放在 `FROM` 之后、语句末尾（如果后面还有排序等子句，则放在它们之前）。

::: tip 知识点
`WHERE` 子句用于设置过滤条件，只返回满足条件的行。通用语法：

```sql
SELECT 列1, 列2, ...
FROM 表名
WHERE 条件;
```

条件中可使用比较运算符（`=`、`<`、`>`）、逻辑运算符（`AND`、`OR`）、`IN`、`LIKE` 等。
:::

### L6 运算符


```sql
select name, age from student where name != '热dog'
```

**解析**：`where` 条件中可使用各种**比较运算符**做判断。`!=` 表示「不等于」，与 `=` 相反；此外还有 `>`（大于）、`<`（小于）、`>=`（大于等于）、`<=`（小于等于），以及判断范围用的 `BETWEEN ... AND ...`。

::: tip 知识点
常用比较运算符：

| 运算符 | 含义 | 示例 |
|--------|------|------|
| `=` | 等于 | `score = 100` |
| `!=` / `<>` | 不等于 | `name != '热dog'` |
| `>` `<` | 大于 / 小于 | `score > 500` |
| `>=` `<=` | 大于等于 / 小于等于 | `age >= 18` |
| `BETWEEN a AND b` | 在 [a, b] 范围内 | `age BETWEEN 18 AND 25` |
:::

### L7 空值


```sql
select name, age, score from student where age is not null
```

**解析**：数据库中的字段可能没有值，即**空值（NULL）**，表示「未知、不存在或未填写」。判断空值**不能**用 `= null` 或 `!= null`——NULL 与任何值比较结果都是未知的，必须使用专门的 `IS NULL` / `IS NOT NULL` 语法。本题用 `age is not null` 过滤掉年龄为空的记录。

::: tip 知识点
空值判断：`列 IS NULL`（为空）、`列 IS NOT NULL`（不为空）。NULL 不等于 0，也不等于空字符串 `''`，它是「没有值」的特殊状态。
:::

### L8 模糊查询


```sql
select name, score from student where name not like '%李%'
```

**解析**：精确匹配（`=`）无法满足「包含某个字」的需求，此时用 `LIKE` 做**模糊查询**。`%` 通配符代表任意长度的任意字符序列，`'%李%'` 表示「名字中任意位置包含『李』字」；前面加 `NOT` 取反，即得到「姓名中不包含『李』」的结果。

::: tip 知识点
`LIKE` 模糊查询的两种通配符：
- `%`：匹配**任意长度**的字符序列（包括 0 个字符）
- `_`：匹配**任意单个**字符

`'李%'` 表示「李」开头，`'%李'` 表示「李」结尾，`'%李%'` 表示包含「李」。搭配 `NOT LIKE` 可排除匹配的行。
:::

### L9 逻辑运算


```sql
select name, score from student where name like '%李%' or score > 500;
```

**解析**：单个 `where` 条件往往不够用，逻辑运算符可把多个条件**组合**起来。`OR` 表示「或」，满足任意一个条件即返回该行——本题结果是「姓李的学生」和「成绩超过 500 的学生」的并集。

逻辑运算符共三个：`AND`（与，所有条件都满足才返回）、`OR`（或，满足任意一个即返回）、`NOT`（非，对条件取反）。多个运算符混用时，用括号明确优先级可避免歧义。

::: tip 知识点
逻辑运算符：
- `AND`：逻辑与，多个条件**都满足**才返回 true
- `OR`：逻辑或，满足**任意一个**条件就返回 true
- `NOT`：逻辑非，否定一个条件（本来是 true，用 `NOT` 后变成 false）

例如：`where (name like '%李%' or score > 500) and age > 20` 表示「姓李或高分」**且**「年龄大于 20」。
:::

### L10 去重


```sql
select distinct class_id, exam_num from student;
```

**解析**：数据表中可能存在重复记录，`DISTINCT` 关键字用于**去重**：去掉结果集中完全相同的行，只保留不同的记录。

`DISTINCT` 作用于 `SELECT` 后面**所有列的组合**——本题是对 `(class_id, exam_num)` 这个二元组去重：只有班级 ID 和考试编号**同时相同**的行才会被合并，而不是分别对两列单独去重。

::: tip 知识点
`SELECT DISTINCT 列1, 列2 FROM 表名` 会对所选列**组合**去重，组合完全相同才算重复。典型场景：统计「班级 + 考试」有哪几种不同组合而不关心出现次数。
:::

### L11 排序


```sql
select name, age, score from student order by score desc, age asc;
```

**解析**：`ORDER BY` 对查询结果排序，放在语句末尾。`DESC` 表示降序（从大到小），`ASC` 表示升序（从小到大，也是默认值，可省略）。

多个排序字段用逗号分隔，**从左到右依次生效**：先按 `score` 降序排，`score` 相同时再按 `age` 升序排，即「成绩高者在前，同分时年龄小者在前」。

::: tip 知识点
排序语法：`ORDER BY 列1 [ASC|DESC], 列2 [ASC|DESC]`。
- `ASC`：升序（默认，可省略）
- `DESC`：降序（必须写明）

排序字段的优先级从左到右递减，先满足前面的排序规则，再处理后面的。
:::

### L12 截断和偏移


```sql
select name, age from student order by age asc limit 1, 3;
```

**解析**：`LIMIT` 控制返回的行数，实现「截断」和「偏移」。`limit 1, 3` 中第一个数字 `1` 是**偏移量（offset）**，表示跳过前 1 条；第二个数字 `3` 是**返回行数**。偏移量从 0 开始计数，偏移 1 即从第 2 条数据开始取。这种「跳过 N 条、取 M 条」的写法是**分页**的核心实现。

::: tip 知识点
`LIMIT 偏移量, 行数`：
- 偏移量从 0 开始（偏移 0 即从头取起）
- 行数是要返回的记录条数

等价写法：`LIMIT 行数 OFFSET 偏移量`，例如 `limit 3 offset 1` 与 `limit 1, 3` 效果相同。网站分页中「第 2 页每页 10 条」对应 `limit 10, 10`。
:::

### L13 条件分支


```sql
SELECT
  name,
  CASE WHEN (age > 60) THEN '老同学'
       WHEN (age > 20) THEN '年轻'
       ELSE '小同学' END AS age_level
FROM
  student
ORDER BY
  name asc;
```

**解析**：`CASE WHEN ... THEN ... ELSE ... END` 是 SQL 中的**条件分支**语法，类似编程语言里的 `if / else if / else`，根据条件在查询结果中动态生成新列。条件从上到下依次判断，**命中第一个满足的条件后不再往下判断**：先看是否大于 60，再看是否大于 20，都不满足则落入 `ELSE`。

本题的 `ELSE` 分支天然覆盖「20 岁及以下」和「无年龄信息（NULL）」两种情况——NULL 不满足任何比较条件，会直接落入 `ELSE`。最后用 `ORDER BY name asc` 按姓名升序输出。

::: tip 知识点
条件分支语法：

```sql
CASE
  WHEN 条件1 THEN 结果1
  WHEN 条件2 THEN 结果2
  ...
  ELSE 默认结果
END [AS 别名]
```

- 按顺序匹配**第一个成立**的条件，后面的不再判断
- 都不成立时返回 `ELSE` 的值（`ELSE` 可省略，省略时返回 NULL）
- NULL 不满足任何比较条件，会直接落入 `ELSE`
:::

## 本章小结

SQL 基础语法篇（L1 ~ L13）核心语法汇总：

| 关卡 | 语法点 | 关键字 |
|------|--------|--------|
| L1 ~ L2 | 全表查询 / 选择查询 | `SELECT ... FROM ...` |
| L3 | 别名 | `AS` |
| L4 | 常量和运算 | 表达式 |
| L5 ~ L9 | 条件查询 | `WHERE`、比较运算符、`IS NULL`、`LIKE`、`AND/OR/NOT` |
| L10 | 去重 | `DISTINCT` |
| L11 | 排序 | `ORDER BY ... ASC/DESC` |
| L12 | 截断和偏移 | `LIMIT 偏移量, 行数` |
| L13 | 条件分支 | `CASE WHEN ... THEN ... ELSE ... END` |

这些语法是 SQL 查询的基础，后续的「函数」「分组聚合」「关联查询」等内容均建立在其上。「`WHERE` 过滤 + `ORDER BY` 排序 + `LIMIT` 分页」的组合已可覆盖不少真实场景的查询。
