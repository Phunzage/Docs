# SQL 分组聚合篇

## 本章概览

上一章我们学习了聚合函数（SUM、AVG、MAX、MIN、COUNT），它们可以针对**整张表**做汇总计算。但实际业务中，我们往往需要的是**分门别类**的统计：每个班级的平均分是多少？每个班级参加每场考试有多少人？哪些班级的总分超过了 150 分？

这些问题单靠聚合函数无法回答，必须把「分组」和「聚合」结合起来。本章共 3 关，从浅入深掌握分组聚合的完整用法：

| 关卡 | 主题 | 核心知识点 |
|------|------|-----------|
| L17 | 单字段分组 | `GROUP BY` 按一个字段分组 + 聚合函数配合规则 |
| L18 | 多字段分组 | `GROUP BY` 按多个字段联合分组 |
| L19 | HAVING 子句 | 分组后的过滤，与 WHERE 的区别 |

::: tip 前置知识
本章默认你已经掌握 [聚合函数](/sql-notes/aggregate-functions/)（SUM、AVG、MAX、MIN、COUNT）的基本用法，如果还不熟悉，建议先回顾上一章。
:::

### L17 单字段分组

**题目**：假设有一个学生表 `student`，包含以下字段：`id`（学号）、`name`（姓名）、`class_id`（班级编号）、`score`（成绩）。请你编写一个 SQL 查询，统计学生表中的班级编号（class_id）和每个班级的平均成绩（avg_score）。

**参考答案**：

```sql
SELECT
  class_id,
  AVG(score) AS avg_score
FROM
  student
GROUP BY
  class_id;
```

**解析**：

`GROUP BY` 的作用是把数据按照指定字段的取值**分成若干组**，同一组内的行拥有相同的字段值。分组之后，聚合函数就不再作用于整张表，而是**分别作用于每一个组**。

本题的执行过程可以这样理解：

1. 先把 `student` 表中所有学生按 `class_id` 分成多个小组（1 班一组、2 班一组……）；
2. 对每个小组分别执行 `AVG(score)`，算出该小组的平均分；
3. 输出时每个小组只返回一行：`class_id` + 该组的 `avg_score`。

`GROUP BY` 的基本语法：

```sql
SELECT 分组字段, 聚合函数(字段) AS 别名
FROM 表名
GROUP BY 分组字段;
```

::: tip 黄金规则
**SELECT 中出现的非聚合列，必须出现在 GROUP BY 中。**

即：只要某列没有用聚合函数包裹（如 `class_id`），又想出现在查询结果里，就必须把它写进 `GROUP BY`。否则数据库不知道该取这一组中哪一行的值，SQL 会直接报错（或在不同数据库中产生不可预期的结果）。
:::

::: warning 注意
分组后每一组只输出**一行**结果，所以未参与分组的普通列（如 `name`、`score`）不能直接出现在 SELECT 中——除非用聚合函数包裹，比如 `COUNT(*)`、`AVG(score)`、`MAX(score)`。
:::

### L18 多字段分组

**题目**：假设有一个学生表 `student`，包含以下字段：`id`（学号）、`name`（姓名）、`class_id`（班级编号）、`exam_num`（考试编号）、`score`（成绩）。请你编写一个 SQL 查询，统计学生表中的班级编号（class_id）、考试编号（exam_num）和每个班级参加每场考试的总学生人数（total_num）。

**参考答案**：

```sql
SELECT
  class_id,
  exam_num,
  COUNT(*) AS total_num
FROM
  student
GROUP BY
  class_id, exam_num;
```

**解析**：

单字段分组只能回答「每个班级有多少人」，而实际需求往往是多维度的：比如想统计**每个班级参加每场考试**的学生人数，就需要同时按 `class_id` 和 `exam_num` 两个字段分组。

多字段分组的写法与单字段几乎一致，只需在 `GROUP BY` 后面用**逗号分隔**多个字段：

```sql
GROUP BY 字段1, 字段2, ...
```

多字段分组的语义是：**把 (字段1, 字段2, ...) 取值组合完全相同的行分到同一组**。本题中：

- `class_id = 1` 且 `exam_num = 1` 的学生分为一组；
- `class_id = 1` 且 `exam_num = 2` 的学生分为另一组；
- `class_id = 2` 且 `exam_num = 1` 的学生又是另一组；
- ……

字段的先后顺序不影响分组结果，但通常把粒度更粗、更常用的字段放在前面，便于阅读。分组字段越多，分组越细，每组包含的行数通常越少。

::: tip 理解技巧
可以把多字段分组想象成「多级抽屉」：先按第一个字段打开外层抽屉（班级），再按第二个字段打开内层抽屉（考试），每个最内层的抽屉就是一个独立的分组。
:::

### L19 HAVING 子句

**题目**：假设有一个学生表 `student`，包含以下字段：`id`（学号）、`name`（姓名）、`class_id`（班级编号）、`score`（成绩）。请你编写一个 SQL 查询，统计学生表中班级的总成绩超过 150 分的班级编号（class_id）和总成绩（total_score）。

**参考答案**：

```sql
SELECT
  class_id,
  SUM(score) AS total_score
FROM
  student
GROUP BY
  class_id
HAVING
  SUM(score) > 150;
```

**解析**：

前两关我们学会了分组和聚合，但分组后得到的结果**不一定全都要**——本题只想要总成绩超过 150 分的班级。此时就轮到 `HAVING` 子句登场了。

`HAVING` 专门用于在**分组聚合之后**对分组结果进行过滤，只保留满足条件的分组。它和 `WHERE` 很像，但**执行时机完全不同**：

| 对比项 | WHERE | HAVING |
|--------|-------|--------|
| 执行时机 | 分组**之前**，先过滤原始行 | 分组**之后**，过滤聚合结果 |
| 能否使用聚合函数 | ❌ 不能（如 `WHERE SUM(score) > 150` 会报错） | ✅ 可以（如 `HAVING SUM(score) > 150`） |
| 过滤对象 | 数据表中的**行** | 分组产生的**组** |
| 未分组时能否使用 | ✅ 可以 | 一般不使用（语义上要求分组） |
| 在语句中的位置 | `GROUP BY` 之前 | `GROUP BY` 之后 |

本题的执行流程：

1. 先按 `class_id` 分组，并计算每个班级的 `SUM(score)`；
2. 再用 `HAVING SUM(score) > 150` 过滤掉总成绩不超过 150 分的班级；
3. 输出剩余班级的 `class_id` 和 `total_score`。

::: tip 一个查询的完整执行顺序
`FROM` → `WHERE`（过滤行） → `GROUP BY`（分组） → `HAVING`（过滤组） → `SELECT`（投影） → `ORDER BY`（排序） → `LIMIT`（截断）。

记住这个顺序，你就能理解为什么 `WHERE` 里不能写聚合函数——因为执行到 `WHERE` 时，分组和聚合还没发生呢！
:::

::: warning 易错点
`WHERE` 和 `HAVING` 不是可以随便互换的。同一个条件写在 `WHERE` 里（过滤行）和写在 `HAVING` 里（过滤组），结果可能完全不同。判断标准很简单：**条件涉及聚合结果（平均值、总和、计数等），就必须用 `HAVING`；条件只涉及原始行的普通字段，用 `WHERE` 更高效**。
:::

## 本章小结

- **L17 单字段分组**：`GROUP BY 字段` 将数据按字段值分组，聚合函数分别作用于每个组；**SELECT 中的非聚合列必须出现在 GROUP BY 中**。
- **L18 多字段分组**：`GROUP BY 字段1, 字段2, ...` 按多个字段的取值组合分组，组合相同的行归为一组，分组粒度更细。
- **L19 HAVING 子句**：`HAVING` 在分组之后过滤分组，**可以使用聚合函数**；`WHERE` 在分组之前过滤行，**不能使用聚合函数**。两者执行时机不同，不能混用。
