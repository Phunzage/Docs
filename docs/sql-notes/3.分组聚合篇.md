# SQL 分组聚合篇

## 本章内容

聚合函数（SUM、AVG、MAX、MIN、COUNT）针对整张表做汇总计算；分组聚合则按字段取值分组后，分别对每个组做汇总。典型需求：每个班级的平均分、每个班级参加每场考试的人数、总分超过 150 分的班级等。本章 3 关：

- L17：单字段分组（`GROUP BY` 按一个字段分组 + 聚合函数配合规则）
- L18：多字段分组（`GROUP BY` 按多个字段联合分组）
- L19：HAVING 子句（分组后的过滤，与 WHERE 的区别）

前置知识：聚合函数的基本用法见 [聚合函数](/sql-notes/aggregate-functions/)。

---

### L17 单字段分组

基本语法：

```sql
SELECT 分组字段, 聚合函数(字段) AS 别名
FROM 表名
GROUP BY 分组字段;
```

参考答案（表 `student`：`id`、`name`、`class_id`、`score`，统计各班平均分）：

```sql
SELECT
  class_id,
  AVG(score) AS avg_score
FROM
  student
GROUP BY
  class_id;
```

**解析**：

`GROUP BY` 按指定字段的取值把数据分成若干组，同一组内的行拥有相同的字段值。分组之后，聚合函数不再作用于整张表，而是分别作用于每一个组。

执行过程：

1. 将 `student` 表中所有学生按 `class_id` 分成多个小组（1 班一组、2 班一组……）；
2. 对每个小组分别执行 `AVG(score)`，算出该小组的平均分；
3. 输出时每个小组只返回一行：`class_id` + 该组的 `avg_score`。

::: tip 黄金规则
**SELECT 中出现的非聚合列，必须出现在 GROUP BY 中。**

未用聚合函数包裹的列（如 `class_id`）若要出现在查询结果里，必须写进 `GROUP BY`，否则数据库无法确定取该组中哪一行的值，SQL 会直接报错（或在不同数据库中产生不可预期的结果）。
:::

::: warning 注意
分组后每一组只输出一行结果，未参与分组的普通列（如 `name`、`score`）不能直接出现在 SELECT 中，除非用聚合函数包裹，如 `COUNT(*)`、`AVG(score)`、`MAX(score)`。
:::

### L18 多字段分组

语法：

```sql
GROUP BY 字段1, 字段2, ...
```

参考答案（表 `student`：`id`、`name`、`class_id`、`exam_num`、`score`，统计每班参加每场考试的人数）：

```sql
SELECT
  class_id,
  exam_num,
  COUNT(*) AS total_num
FROM
  student
GROUP BY
  class_id, exam_num;
```

**解析**：

单字段分组只能回答「每个班级有多少人」，统计「每个班级参加每场考试」的学生人数时，需要同时按 `class_id` 和 `exam_num` 两个字段分组。多字段分组的写法与单字段一致，只需在 `GROUP BY` 后用逗号分隔多个字段。

多字段分组的语义：**把 (字段1, 字段2, ...) 取值组合完全相同的行分到同一组**。本题中：

- `class_id = 1` 且 `exam_num = 1` 的学生分为一组；
- `class_id = 1` 且 `exam_num = 2` 的学生分为另一组；
- `class_id = 2` 且 `exam_num = 1` 的学生又是另一组；
- ……

字段的先后顺序不影响分组结果；通常把粒度更粗、更常用的字段放在前面，便于阅读。分组字段越多，分组越细，每组包含的行数通常越少。

::: tip 理解技巧
多字段分组可类比「多级抽屉」：先按第一个字段打开外层抽屉（班级），再按第二个字段打开内层抽屉（考试），每个最内层的抽屉就是一个独立的分组。
:::

### L19 HAVING 子句

语法：

```sql
SELECT 分组字段, 聚合函数(字段) AS 别名
FROM 表名
GROUP BY 分组字段
HAVING 聚合函数(字段) 条件;
```

参考答案（表 `student`：`id`、`name`、`class_id`、`score`，统计总成绩超过 150 分的班级）：

```sql
SELECT
  class_id,
  SUM(score) AS total_score
FROM
  student
GROUP BY
  class_id
HAVING
  SUM(score) > 150;
```

**解析**：

分组聚合后得到的结果不一定全都要——只保留总成绩超过 150 分的班级时，需要用 `HAVING` 子句在分组聚合之后对分组结果进行过滤。`HAVING` 与 `WHERE` 类似，但执行时机完全不同：

| 对比项 | WHERE | HAVING |
|--------|-------|--------|
| 执行时机 | 分组**之前**，先过滤原始行 | 分组**之后**，过滤聚合结果 |
| 能否使用聚合函数 | ❌ 不能（如 `WHERE SUM(score) > 150` 会报错） | ✅ 可以（如 `HAVING SUM(score) > 150`） |
| 过滤对象 | 数据表中的**行** | 分组产生的**组** |
| 未分组时能否使用 | ✅ 可以 | 一般不使用（语义上要求分组） |
| 在语句中的位置 | `GROUP BY` 之前 | `GROUP BY` 之后 |

执行流程：

1. 先按 `class_id` 分组，并计算每个班级的 `SUM(score)`；
2. 再用 `HAVING SUM(score) > 150` 过滤掉总成绩不超过 150 分的班级；
3. 输出剩余班级的 `class_id` 和 `total_score`。

::: tip 一个查询的完整执行顺序
`FROM` → `WHERE`（过滤行） → `GROUP BY`（分组） → `HAVING`（过滤组） → `SELECT`（投影） → `ORDER BY`（排序） → `LIMIT`（截断）。

执行到 `WHERE` 时分组和聚合尚未发生，因此 `WHERE` 中不能写聚合函数。
:::

::: warning 易错点
`WHERE` 和 `HAVING` 不能随意互换。同一个条件写在 `WHERE` 里（过滤行）和写在 `HAVING` 里（过滤组），结果可能完全不同。判断标准：条件涉及聚合结果（平均值、总和、计数等）必须用 `HAVING`；条件只涉及原始行的普通字段，用 `WHERE` 更高效。
:::

## 本章小结

- **L17 单字段分组**：`GROUP BY 字段` 将数据按字段值分组，聚合函数分别作用于每个组；**SELECT 中的非聚合列必须出现在 GROUP BY 中**。
- **L18 多字段分组**：`GROUP BY 字段1, 字段2, ...` 按多个字段的取值组合分组，组合相同的行归为一组，分组粒度更细。
- **L19 HAVING 子句**：`HAVING` 在分组之后过滤分组，**可以使用聚合函数**；`WHERE` 在分组之前过滤行，**不能使用聚合函数**。两者执行时机不同，不能混用。
